# Idiomas (español / inglés)

El sitio completo está disponible en **español** e **inglés**. El selector
**ES | EN** está en el header (tablet y escritorio) y en el menú lateral (móvil).

- Idioma inicial: el que eligió el usuario (se recuerda en el dispositivo,
  clave `kom-lang`); si no hay, el del navegador o teléfono (español → ES,
  cualquier otro → EN).
- Al cambiar se actualizan `<html lang>`, el título de la pestaña y la
  descripción. Fechas y nombres de país también se muestran en el idioma.

## Dónde va cada texto

| Tipo de texto | Dónde | Cómo |
|---|---|---|
| Interfaz (botones, títulos, avisos, `aria-label`, `alt`…) | `src/i18n/messages/es.ts` y `en.ts` | Misma clave en los dos archivos |
| Contenido (personajes, habilidades, mapa, historia, equipo, herramientas) | `src/data/*.ts` | `{ es: '…', en: '…' }` |

En un componente:

```tsx
import { useI18n } from '../../i18n'

const { t, l } = useI18n()
<h2>{t.map.title}</h2>              // texto de la interfaz
<p>{l(location.description)}</p>    // contenido { es, en }
<p>{t.team.photoOf(member.name)}</p> // texto con datos variables
```

## Por qué siempre se traduce TODO

1. **TypeScript**: `en.ts` usa el tipo de `es.ts`; si falta o sobra una
   clave, no compila. En `src/data`, los campos de texto son de tipo `L`
   (`{ es, en }`): un personaje o escenario nuevo sin inglés no compila.
2. **`npm run check:i18n`** (se ejecuta en cada `npm run build`): revisa
   todos los componentes y falla si encuentra texto escrito directamente en
   JSX, en atributos visibles (`aria-label`, `alt`, `title`, `placeholder`…)
   o cualquier cadena en español fuera de `src/i18n` y `src/data`.
   Muestra el archivo y la línea de cada caso.

Los nombres propios que no cambian (King of Music, nombres de personajes)
se escriben igual en ambos idiomas.

## Lo que no se traduce

- Las **reseñas** que escriben los usuarios se muestran tal como se
  publicaron.
- El texto que forma parte de **imágenes o videos** (storyboard, logos).
